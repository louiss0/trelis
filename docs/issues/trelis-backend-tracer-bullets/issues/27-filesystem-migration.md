## Answer

Implemented on `ticket/backend-27-filesystem-migration` in commits `c634946` (shared profile/session/adapter ownership and wrapped styled guidance for `PathInput`), `6adf6e8` (entry and review help coverage), `f122574` (browser migration with stage-specific help), `6af2faf` (README), `7ddc5cf` (terminal outcomes, caveats and shared-feedback coverage) and `25b0945`/`5b00c62` (evidence).

`PathInput`, `FilePicker` and `DirectoryPicker` now resolve an `OutputProfile`, accept `terminal`, `outputProfile` and `session` like the other migrated prompts, lease and restore an explicit adapter once, and reject competing invocation configuration on an attached prompt. A rich synthetic source must declare cursor support and positive geometry; automatic mode falls back to linear. Guidance, listings, warnings and review are painted through the shared safe writer (`DisplayText` escaping, declared-width wrapping, component `ColorTheme` when the profile permits colour), and an attached session shares its reader, writer, repaint and feedback.

Path semantics are unchanged: literal native paths with `..` retained, no shell expansion, quote stripping, link canonicalization or working-directory change, drive-relative Windows rejection, existing-target and typed-target policy, fail-closed inspection, the resolved-candidate review with `edit` returning to entry, per-open link approval, listing refresh, stale-reference detection, hidden-entry toggling and parent navigation. The later-operation and no-sandbox caveats stay visible outside help and are restated in help.

Rich `Ctrl+T` and linear `/help` now open component help rather than generic editor instructions, with a separate page for entry, browsing, literal-path entry and review; help names the current stage first and then the wider workflow, keeps `/help` out of the draft (cleared instead of typed, with `\/help` still entering the literal path), and dismissal repaints and retains the draft, listing or review candidate. Mutation-checking the help wiring fails four of the new tests, so the coverage depends on the component help.

On Windows NT 10.0.26200.0 with Dart SDK 3.13.2, targeted path/browser suites passed 57 tests, the acceptance matrix and session suites passed 163 tests, `dart analyze` reported no issues, documentation links passed, and the full suite passed 837 tests at revision `7ddc5cf`. Evidence and limitations are recorded in `assets/evidence/trelis-backend/27-filesystem-migration.md`; native PTY, visible GUI/NVDA, Linux/macOS CI, short-screen resize, fault-injection and final-gate verification remain outstanding, and the transcript-style rich output means vertical overflow is scrollback rather than an alternate screen.
