## What was built

- `lib/src/prompt_structure.dart`: the underline and label-band half of the
  structural vocabulary.
  - `HeadingGlyphs` gained one field, `bandGlyph`, with `drawsBand` and
    `band(cells)`, because a label band is chrome that is composed at the width
    the stage actually has, exactly as `ruleGlyph`/`rule(cells)` already is.
    `compactPrefix` keeps one fill character as the narrow marker when a grammar
    draws a band, so a stage too narrow for a filled row still shows the
    structure instead of degrading to the reference presentation.
  - `_lineHeading` / `_asciiLineHeading` declare the underlined question: no
    heading decoration, two-cell body indent, a hint at the same indent and an
    underline of `─` (portable counterpart `-`).
  - `_blockHeading` / `_asciiBlockHeading` declare the label band: an uppercase
    heading drawn as a filled row of `█` (portable counterpart `#`), a two-cell
    body indent and a hint at the same indent.
  - `usesStructureHeading` names the nine decorated structures and
    `headingGlyphsFor` returns the two new vocabularies.
  - `structureBandWidthCap` (80), `structureBandWidth` and `structureBandRow`
    are the pure width and spelling helpers. `structureBandRow` embeds the label
    in a filled row, keeps the padding first and the trailing fill second when
    the width narrows, and keeps a label that is too wide whole rather than
    truncating it. None of them holds state or touches a terminal.
- `lib/src/themes/line_theme.dart`, `block_theme.dart`: `LineTheme` and
  `BlockTheme` with all 38 typed static factories each, generated by
  `tool/generate_theme_factories.py` from `plain_theme.dart` and forwarding
  `structure:` with their own value. Exported from `lib/prompty.dart`.
- `_StructureSpine` (internal, `lib/src/text_input.dart`) gained the two
  grammars through the seam the heading grammars already used, so every
  component that renders through the spine renders them:
  - `_headingWidth` caps a band grammar at `structureBandWidth`, the same
    bounded total width a rule uses, so the band spans the stage instead of
    trailing off wherever its label ends, and the heading, the body rows and the
    hint are all measured against that same width.
  - `_writeBand` composes the heading as one band row per wrapped label line.
    The fill is the band: it is printed in every capability profile, so the
    hierarchy survives monochrome output and redirected logs. Where the profile
    declares `styles: supported` the same row is additionally printed inverted
    (`ESC[7m`), which strengthens the band without ever being the reason it can
    be seen.
  - The underline needs no new path: it is the grammar's measured rule, drawn
    under the heading in the palette's border role, in both interaction modes.
- The band and the underline are the structure's chrome only. No component
  changed its task behavior, accepted values, validation, choice references,
  input bindings, focus, selection or completion outcome, and no answer data,
  literal command, example, identifier or choice reference passes through the
  heading spelling: the block grammar's capitals reach the heading a component
  owns and nothing else.
- The atlas hint casing (`ENTER TO CONTINUE`) is deliberately **not** applied.
  The compact hint carries literal commands and examples (`Exact /help and
  /cancel are commands`), so re-casing it would transform a literal command; the
  block grammar keeps the atlas heading casing and leaves the hint's own
  spelling intact.

  - `test/theme_line_block_framing_test.dart` (215 tests)

## Structure grammar check

`test/theme_line_block_framing_test.dart` runs every applicable interactive
component (all 34) through each of the two structures in both interaction modes,
plus the four feedback components per structure (and both modes for the three
live ones), and asserts:

- **Line** — the question opens the stage at the reference column and keeps its
  own casing; the underline is drawn below the heading block and spans the
  measured stage width (72 of 72 columns, 80 above the cap); the body rows, the
  compact hint and the outcome rows are indented two cells under it; no row of
  the run carries enclosure chrome (`┌ ┐ └ ┘ ╭ ╮ ╰ ╯ ╔ ╗ ╚ ╝ ║ ├`) and no row
  falls back to the reference `> ` live marker.
- **Block** — the first row is a filled band that contains the component's label
  spelled in capitals and is filled to the measured stage width; body rows,
  compact hint and outcome rows are indented two cells under it; the band is
  present with no colour and with inverse styling unavailable; declared style
  support adds `ESC[7m` around the same band instead of replacing it.
- The underline and the band are measured against the same cap: a 200-column
  profile draws them at 80 cells, everything else stays inside the 120-cell
  prompt cap, 24 columns keep every line inside 24, and 8 columns keep both the
  decoration and the live row inside 8.
- The rich vocabulary is Unicode (`─`, `█`, `▶`) and an `automatic` glyph
  profile falls back to the portable ASCII counterpart (`-`, `#`, `> `).
- A palette `foreground` styles the stage while the accepted value is unchanged.
- The answer data is never case-transformed: `Ada Lovelace` stays `Ada Lovelace`
  under a capitalised band, the band itself never contains the draft, a literal
  `/Help` in validation text keeps its spelling, a protected message keeps its
  `\u{0007}` spelling, a masked password is never echoed, an unavailable choice
  keeps its reason and a reported outcome stays in the stage.
- Stage help keeps the structure grammar; a rich presentation re-opens the
  decoration for each presentation; a linear run draws it once and a keystroke
  never duplicates it.
- The real caret keeps the structure's own live marker (`  › `, `  ▶ `), stays
  inside the declared width and shows the real draft; a resize repaints that row
  at the new width (`  ▶ <efgh` at 10 columns) without drawing a second stage
  and without recording a second presentation event.
- Emphasis never reports a selection: no inverted segment contains a choice
  label, the band is the only inverted row, a retained default is not marked as
  accepted, and checked/selected, focused and unavailable stay distinct facts.
- `TextInput`, `Select`, `Confirm` and `Password` produce the same outcome as the
  reference presentation in both modes, with and without inverse styling.
- Standalone feedback gains the structure's live marker without a frame for
  `Text`, `Progress`, `Spinner` and `MultiSpinner` in both modes.
- The two grammars never render the same bytes, and neither renders the bytes of
  the reference presentation.
- **Byte identity of the merged structures** — `test/theme_line_block_framing_test.dart`
  pins the exact linear `TextInput` bytes of all thirteen structures delivered
  earlier (`plain`, `rail`, `branch`, `box`, `round`, `double`, `minimal`,
  `ascii`, `chevron`, `bracket`, `form`, `ledger`, `colon`) and asserts them
  unchanged. The existing byte tests for the reference, rail and branch
  presentations (`test/theme_structure_rendering_test.dart`) also still pass
  unchanged.

### Byte identity across the wider surface

committed test; the pinned-bytes test above is the durable contract.

## Limitations and remaining work

- The atlas block specimen paints only ` LABEL ` and relies on reverse video.
  This implementation always draws the textual fill and adds the inversion where
  the output declares style support, because the resolved contract requires the
  hierarchy to survive monochrome output and redirected logs. A reader of a
  styled terminal therefore sees a filled band rather than the specimen's bare
  padded label.
- Inverse emphasis uses the monochrome SGR style (`ESC[7m`) gated on
  `OutputProfile.styles`. An `automatic` or unknown style capability is treated
  as unsupported, exactly as an unknown glyph capability falls back to ASCII, so
  no emphasis is invented for an output that never declared it. The emphasis is
  not a palette role: it is style, so it survives a palette with no selection
  colours and adds nothing to a redirected log.
- The atlas line specimen shows a blank rule row between the underline and the
  choices. This implementation does not add an unattributed empty row, because a
  blank row in a sequential transcript carries no meaning; the breathing row an
  enclosure draws inside its frame has no counterpart here, and the underline
  already separates the question from the body.
- The atlas hint casing (`ENTER TO CONTINUE`) is not applied, because the compact
  hint is where literal commands and examples are quoted.
- At 8 columns and below the band fills one marker per wrapped label line, so the
  band reads as a stack of `█` rows rather than one row. Below 3 columns no fill
  fits at all and the label is kept alone; the structure's body indent, live
  marker and hint still distinguish it from the reference presentation.
- The live response row costs four cells (`  › `, `  ▶ `) like the ledger's
  `   > `. At 4 columns that marker plus the one-cell overflow indicator is
  wider than the terminal, so the narrow-width evidence is taken at 8 columns;
  this is the same pre-existing limit every wide-marker grammar has, not a
  property of these two grammars.
- A component that finishes editing one value can write the next stage heading on
  the same physical line as the caret row it just left (`MaskedInput` does this
  for every structure, including the merged ones). The decoration itself is
  never mis-measured, but the two rows share one display line in that transcript.
- The atlas line grammar marks the focused choice with `›` and the atlas block
  grammar with `▶`. Those glyphs are used here as each structure's live-row
  marker; the choice rows keep the shared focus-marked rows every structure
  already had, so a focused choice is still marked by the component, not by the
  structure.
- No native-terminal visual qualification was performed: every result here is
  scripted output, not a screenshot or a manual terminal review. Windows native
  and GUI probe evidence for the theming families remains a separate ticket.

## Conclusion

The `LineTheme` and `BlockTheme` factory namespaces, the underline and label-band
vocabulary and its composition helpers, and the two grammars across every
applicable interactive and feedback render path are implemented, verified by
3470 passing tests, and committed. All thirteen previously merged structures
keep the bytes they wrote before this ticket, both in the pinned-bytes test and
in the 165-scenario probe comparison. Protected content, accepted values, choice
references, input bindings and completion outcomes are unchanged, the block
band's hierarchy is textual rather than colour-dependent, and emphasis never
substitutes for a selection fact. The ticket is **resolved** with the worktree
ready for merger.
